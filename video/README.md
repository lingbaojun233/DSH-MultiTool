# video — 看视频模块

给面板用：用户发来一段视频，它先让多模态模型看懂画面，再把描述交给 io，由**大肥鱼用自己的口气**回应。

## 为什么要拆成两段

```text
视频 → [本模块] → 视频描述（时间轴 + 内容）
                       ↓
                  [io /v1/input] → 人格 + 记忆生效 → 大肥鱼的回复
```

如果让多模态模型直接扮演大肥鱼，人格和记忆就用不上了。拆开之后：**看画面**用视觉模型，**说话**回到 DSH 核心，两边各自最优。

## 它现在也"听"声音

链接视频下载后，会把同一个文件交给听力模块（`listen` 8769 → 8771）：

```text
视频文件 ─┬─ ffmpeg 抽帧 ─→ 视觉模型 ─→ 画面描述
          └─ listen /v1/hear ─→ 转写 + 声音事件（静音/响动/持续背景声）
                                    ↓
                              一起交给 io → 大肥鱼
```

面板里「画面描述」下面会多一块声音信息。实测一段 10 秒短片：

```text
声音概况：全长约 10 秒，其中 8 秒有声音；只有零星的人声/语气词
声音事件：0:00-0:08 持续有声约 8 秒（峰值 -19.6 dB）
她说的：挺可爱的 值得一看 就是声音只有一声「阿」
```

**一个刻意的约束**：视觉模型的提示词里写明「你只拿到了画面帧，没有音频，不要对声音下结论」。不这么写，它就会用画面去猜音效，等于拿视觉冒充听觉。

## 输入三条路

| 来源 | 做法 | 能听声音？ |
| --- | --- | --- |
| 本地文件 + 勾「连声音一起听」 | **浏览器原片直传**（XHR 流式 PUT，边收边写盘）→ 服务器抽帧 + 听音轨 | ✅ |
| 本地文件（不勾） | 浏览器解码抽 N 帧，只传 JPEG | ❌ |
| 网络链接 | 服务器 yt-dlp 下载 → 抽帧 + 听音轨 | ✅ |

**为什么原片直传不用 base64**：base64 会多 33% 体积，而且要在内存里攒整个文件。现在是 `PUT /api/video/upload` 边收边 `createWriteStream`，2GB 的片子也不会把面板撑爆，浏览器还能用 `upload.onprogress` 出进度条。

上传落盘在 `data\uploads\<uuid>.<ext>`（模块目录之外，push 不会破坏），分析完立刻删除；30 分钟没动过的也会被清扫。实测 4.8MB 上传 3.4 秒，分析 37 秒，处理后残留 0 个文件。

## 输入两条路

| 来源 | 做法 | 依赖 |
| --- | --- | --- |
| 本地文件 | **浏览器**解码、抽 N 帧 JPEG，只上传帧 | 无 |
| 网络链接 | 服务器 yt-dlp 下载 → ffmpeg 抽帧 | `tools\yt-dlp.exe` + `tools\ffmpeg` |

本地视频**不上传原文件**：60 MB 的录像传上去要几十秒，而在浏览器里抽 8 帧不到 1 秒。

## 模型

走阿里云 MaaS 网关（OpenAI 兼容），实测可用的看图模型：

| 模型 | 看图 | 备注 |
| --- | --- | --- |
| `qwen3.8-flash` | ✅ | 默认，6 帧约 11s |
| `qwen4-max` | ✅ | 备用（配置里 fallbackModel） |
| `qwen3.7-plus` | ✅ | 较慢 |
| `qwen3.7-max` / `glm-5.3` | ❌ 400 | 不吃图片输入 |

`config.json` 里改 `model` 即可换。不可用时自动退到 `fallbackModel`。

### 时间是怎么压下来的

| 改动 | 效果 |
| --- | --- |
| 抽帧从「每帧一次 ffmpeg」改成 **一次 fps 滤镜出全部帧** | 省掉 8 次进程启动 |
| 听音轨与视觉分析**并行**（互不依赖） | 5.1s 藏在 10.8s 背后，净省 5s |
| 帧数 8 → 6、边长 896 → 768、`max_tokens` 1600 → 900 | 视觉从 25s 降到 10.8s |
| 发给 io 的文本去掉整条时间线 | io 少 ~800 token |

同一段 4.8MB 录屏：**30~37s → 16.6s**（视频内部 11.6s + io 约 5s）。

## 接口

```text
GET  /v1/health        → {ok, model, hasKey, ffmpeg, ytdlp}
POST /v1/analyze       → {frames:[{t,dataUrl}], text}     浏览器抽好的帧
POST /v1/analyze-url   → {url, text, frames}              服务器下载后抽帧
```

返回 `{ok, model, synopsis, timeline[], highlights[], onScreen, usage}`。

面板侧还有一层 `/api/video/analyze` 和 `/api/video/url`：它会在拿到描述后**继续调 io**，把大肥鱼的回复一起返回。

## 配置

`config.json`（可进仓库）放非敏感项；**`secrets.json` 放 apiKey，已 gitignore**，部署时单独传。

```json
{ "gateway": "...", "model": "qwen3.8-flash", "maxFrames": 16, "frameMaxSide": 896 }
```

## 已知限制

- **抽帧是均匀取样**，不是场景检测。跳剪很快的视频，关键帧可能正好被跳过 —— 要更准就得加场景变化检测。
- **不看音频**。目前只喂画面，没有转写台词。
- **链接受平台限制**：B 站等要登录态的内容 yt-dlp 会失败，报错会原样返回。
- **单次成本不低**：8 帧约 4300 输入 token（约 25s），16 帧翻倍。帧数是唯一有效的成本旋钮。
